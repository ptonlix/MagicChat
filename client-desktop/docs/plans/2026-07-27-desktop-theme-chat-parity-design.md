# 桌面端主题与聊天能力对齐设计

## 目标

本轮聚焦桌面端四项体验：原生标题栏与应用主题一致、服务器配置页改为更接近飞书的克制布局、补齐会话免打扰及状态图标、修复 macOS 菜单栏图标显示为彩色的问题。聊天之外的 Web 差异只形成清单，不在本轮扩大实现范围。

## 方案选择

### 主题同步

采用“Renderer 主题为唯一用户配置源，Main 同步原生外观”的方案。`ThemeProvider` 继续管理 `system/light/dark` 和本地存储，同时通过窄类型 Desktop Bridge 将主题源发送给 Main。Main 使用 Electron `nativeTheme.themeSource` 更新原生标题栏，并同步窗口背景色，避免关闭按钮区域与页面割裂。相比为不同平台分别写死标题栏颜色，这一方案能同时覆盖跟随系统、明亮、暗色三种模式，且不会引入多套配置。

### 服务器配置页

保留单服务器约束和现有提交逻辑，只调整呈现。页面改为飞书式“轻量品牌信息 + 聚焦连接卡片”的双栏结构，减少大面积装饰渐变和圆形伪元素；暗色模式使用主题变量而不是固定白底/绿色。表单强化服务器地址为主操作，显示名称作为次要可选项，并保留可信服务器提示与错误反馈。

### 会话置顶与免打扰

桌面端已具备置顶 API、排序和部分菜单，本轮在现有链路上补齐免打扰 API、Provider 状态更新、实时事件订阅和 Sidebar 操作。置顶会话显示小型 Pin 图标；免打扰会话显示 BellOff 图标，并将未读数字降级为红点，保持与 Web 端一致。内置助手继续不显示置顶操作，但允许免打扰。

### macOS 菜单栏图标

继续复用现有图标文件，但在 macOS 创建 Tray 前将缩放后的 `NativeImage` 标记为 Template Image。macOS 会根据菜单栏背景自动渲染白色或深色单色图标，避免当前绿色品牌图标在顶部菜单栏中过于突兀。Windows 与 Linux 保持现有彩色图标。

## 验证

新增或扩展单元测试覆盖 Bridge 契约、主题同步调用、Tray 模板图标、免打扰 API、Sidebar 菜单和状态图标、实时事件状态更新。完成后运行桌面端定向测试、类型检查、Lint、边界检查和生产构建。
